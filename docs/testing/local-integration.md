# Isolated integration and hosting verification

Run `pnpm run build`, then `pnpm run test:integration` with `SUPABASE_TEST_URL`, `SUPABASE_TEST_ANON_KEY`, `SUPABASE_TEST_SERVICE_ROLE_KEY` from a freshly reset local Supabase and `SUPABASE_TEST_ISOLATED_LOCAL=true`. The command fails without all configuration or when the URL is not loopback HTTP. The acknowledgement asserts that this local instance contains disposable test data; do not forward a production database onto that port. All seven database suites run serially to avoid shared lease/order cleanup races. Normal `pnpm test` retains optional DB skips for offline unit work; CI's mandatory integration step cannot silently skip missing configuration.

CI runs database security, API, fencing, provider operation, refund, cancellation, and retained checkout suites. These use fixture provider behavior. The separate manually dispatched staging-provider-smoke workflow checks staging readiness and provider credentials; it is not proof of a real capture, refund, shipping cancellation, or webhook replay journey.

`node --test tests/hosting.test.cjs` checks static startup independent of working directory, SPA HTML navigation, real asset 404s, missing build failure, runner refusal, and deployment redirect configuration. Browser commerce journeys remain a gate: use disposable local users/orders, mock provider endpoints, and mount the real client against the isolated API; never start development workers with production credentials. Existing responsive tests are layout audits and do not establish checkout/payment behavior.

## Deployment gates requiring infrastructure access

The checked-in nginx config returns HTTP 308 for `www.muvira.in`, preserving `$request_uri` (path and query). Dokploy must route BOTH apex and www to this client and provision valid TLS certificates for both hosts. Verify externally with `curl -I 'https://www.muvira.in/products/example?source=check'`: expected Location is `https://muvira.in/products/example?source=check`. Verify apex deep links, missing JS/CSS 404 responses, and the API readiness endpoint after rollout. DNS, ingress routing, TLS and live redirects have not been verified by repository checks.

Repository config review: Compose requires `ALLOWED_ORIGINS` and client build argument `VITE_AUTH_REDIRECT_URL`; neither has a production default. Set production CORS to `https://muvira.in` and auth redirects to the actual canonical apex callback/reset URLs used by the app. Supabase `config.toml` intentionally configures localhost for local Auth only; separately inspect hosted Supabase Site URL and allowed redirect URLs and Google OAuth provider callback configuration. Do not replace local config with production URLs. `.env.example` currently uses placeholder hosts, so it cannot establish deployed canonical configuration. No hosted configuration was inspected or changed.
