# Muvira interaction contract

Visual rules live in [DESIGN.md](DESIGN.md). Existing API authorization, payment, inventory and reconciliation behavior remains authoritative.

- Commerce and customer mutations go through existing services and the Express API. Money remains integer paisa; display uses Indian rupee formatting.
- Authentication and admin guards remain in place. Visual-test auth is isolated to a test Vite server; no production bypass exists.
- Save, cart and purchase actions retain their current promises, pending state, failure feedback and confirmed-success destinations. Provider outcomes are never inferred from UI state.
- Storefront lists retain supported search, category, availability, price and sort parameters, explicit pagination, and scroll-to-results behavior. Reset beside the Filter heading retains existing semantics: Shop clears all parameters; Search preserves its committed query. The empty-results recovery action remains available. Result cards have no duplicate filter chips or clear-filter toolbar. Search drafts and price inputs follow browser history, including rapid clear/back navigation. Collection shortcuts remain on one horizontally scrollable row, with visible scrollbars and keyboard-reachable links; revealing the active collection never scrolls the document. New filters are not invented.
- Shared Modal and useDialogFocus own Escape, focus trapping and restoration. AuthDialogProvider owns openAuth({ mode, returnTo? }) and closeAuth(). Sign-in, signup, recovery and confirmation switch within the same popup, preserve email and clear passwords on switching or closing. Opening and dismissal preserve URL, filters, scroll and cart. Ordinary navigation closes authentication. Mobile navigation/cart drawers close first; dismissal restores the original trigger or the persistent account/bag/menu control. Navigation disclosure links and quantity choices extend Dropdown, including arrow keys, Escape and focus behavior. The photographic collections variant is opt-in; default catalog/admin selectors retain their layout. Merchant navigation follows showInNavbar, while discovery includes every active collection. Search uses this same modal. Mobile admin navigation uses the same primitive.
- Only a loaded account profile completes authentication. Profile failures expose retry and sign-out in the popup; stale completions after dismissal or form switching cannot navigate. Signup requiring email confirmation shows Check your email without claiming authentication. Buy now adds the chosen quantity once and requests authentication only after confirmed addition. Guards alone own protected access: guest checkout opens over /cart; account, order and admin access opens over /. Legacy /signin, /signup and /login replace with / plus typed popup state. Validated same-origin return paths retain query strings/hashes and cannot target auth-entry routes. /reset-password remains available for emailed recovery links.
- Loading, error and empty states stay distinct. Optional campaigns/contact sections render only when configured. Content failures never introduce fallback commercial data.
- Checkout uses server totals and Razorpay Custom Checkout. Continue to payment leaves the order editable; Review payment prepares it idempotently, freezes its server snapshot, and exposes a separate user-initiated Pay action. Unknown/authorized outcomes disable retry until reconciliation permits it. Cancellation only promises release after server confirmation. Payment verification, confirmed success, tracking, invoice, refund and reconciliation preserve their existing state rules. Card fields remain transient and go directly to Razorpay; no payment credentials enter Muvira services or storage.
- Email preferences remain the only supported notification control. No wishlist, newsletter, subscriptions, SMS, push, Apple OAuth or returns are added.
- Existing native form validation is retained for this presentation migration. Dropdown is canonical for authored choices. Every field has a label, 16px minimum text and a visible focus state.
- Keyboard, touch, reduced motion, narrow layouts and enlarged text are verified in browser fixtures. Test fixtures block provider calls and reject unhandled mutations.

The generic premium static auditor recommends disabling native validation. That recommendation is intentionally deferred here: disabling it without replacing every form's validation would weaken the existing commerce and account behavior. Likewise, existing resizable textareas remain available. This presentation migration preserves those controls and documents the decision instead of silently disabling validation or resizing.

## Shopping and image interaction

Customer destination actions rely on visible text, including “View order” on each order card. Decorative arrows are absent from labeled links and actions. Retain functional gallery/carousel/lightbox controls, pagination, breadcrumb separators, dropdown/disclosure chevrons and dedicated back navigation. Search submission keeps a visible text label on phones. Removing an icon must preserve semantic links/buttons, hover and keyboard focus states and 44px targets. Admin controls follow the separate admin workspace contract below.

Collection images and vertical product-card photographs fill their frames; product cards use centered crops, with 1.06× / 350ms zoom restricted to fine pointers and no reduced-motion preference. Actions remain visible for touch and keyboard. StoreImage owns image failures and exact-source reviewed focal points; it does not create substitute merchandise. The shared gallery's square main photograph uses object-cover, while its lightbox, quick-view and horizontal product-card images preserve complete originals. Thumbnail selection, arrows and mobile swipe choose the same original that main-image/enlarge activation opens. One photograph has no redundant image-navigation controls; zero images and failed sources remain truthfully unavailable. Product identity remounts the gallery to reset selection, zoom and pan. Lightbox image navigation resets zoom/pan, supports 1×/2×, reset, labeled pan buttons, pointer dragging and arrow keys, and restores the opener on Escape. Main-page purchase actions precede supporting description/highlights without changing cart quantity or Buy now authentication semantics.

CustomerPageHeading and AccountNavigation own repeated account headings and navigation. Saved-address links resolve their hash after route content mounts. Order confirmation displays only owned order items after the existing paid-state check; pending and unknown outcomes keep their existing distinct recovery actions. Care information appears only when the current product metadata supplies it.

Dropdown selection restores its trigger after a pending disabled state ends, without taking focus from another control. Keyboard opening uses the committed popup rather than a delayed focus callback that could target an exiting menu. Lightbox content must fit horizontally and remain scrollable vertically at 200% text.

Only the header collections Dropdown opts into hover. Fine-pointer entry opens immediately without changing focus; travel into the panel cancels the 150ms exit timer. Clicking a trigger opened by hover keeps the panel open. Keyboard focus inside holds the panel open after pointer exit. Escape also dismisses a hover-open panel while focus remains in another control, preserving that outside focus. Touch toggling, arrow-key navigation, Escape with focus restoration, outside interaction and route dismissal remain available. Other Dropdown instances preserve their default interaction. Authentication uses a single brand/title header, and busy Buttons preserve geometry and accessible labels. Customer icon/label groups keep icons beside the first label line; whole controls stack before short labels are squeezed.

The header publishes its measured height through `--store-header-height`. Product panels and commerce summaries use the shared viewport-fit hook before sticking. Account and results scroll targets use the same offset. Header search stays visible on phones and enlarged text, while checkout and payment outcomes use the focused header variant. Mobile purchase actions yield to text entry and the footer.

Product specifications are an internal presentation model: explicit labeled description facts supplement metadata, metadata wins on conflicts, empty/unavailable values are omitted, and the complete source description stays available. No API, database or shared commerce contract changes support this presentation.


## Admin workspace behaviour

- Existing `/admin` routes, authorization guards and Express endpoints remain authoritative. The visible failures section is called Issues & recovery; its URL remains `/admin/failures`.
- Overview metrics are real today/all-time aggregates, never trend estimates. Pending/confirmed links set actual order-status filters. The low-stock KPI counts active products; the inventory preview and inventory list explicitly include hidden products. Statistics, recent orders, inventory and recovery have independent loading/error/retry states.
- Orders expose the existing status, payment-status and fulfillment-status filters. Search is explicitly submitted or cleared. Customer-email/order search stays in the mounted admin workspace's transient memory; it is not put in URLs or persistent storage. It survives order-detail navigation and back while that workspace remains mounted; reload or leaving administration clears it.
- Product search, category selection, catalog tab and page are URL-owned. Inventory uses independent `inventory_page`, `inventory_category` and `low_stock_only` parameters. Coupons retain URL-owned paging, and recovery queues preserve their existing independent URL state. Committed filters reset the owning page; out-of-range API pages clamp safely. Page size is 20; categories paginate the complete fetched list locally.
- Explicit search avoids per-keystroke requests. Clearing is immediate and returns focus to the search field. Superseded reads cannot overwrite the current result. Pagination preserves scroll-to-results and respects reduced motion.
- Products, categories and coupons are list-first, with shared Modal drawers. Every admin dialog, confirmation and mobile navigation uses the right-side presentation (480px standard, 640px wide; full width below 768px). Header and footer remain reachable while the body scrolls. Footer submit buttons explicitly target their owning form; saving products cannot submit media forms. Tab controls support arrow keys, Home and End. Closing a changed editor offers Keep editing or Discard changes. Form DOM and selected uploads stay mounted while deciding. Busy editors and confirmations cannot be dismissed by their close control, backdrop or Escape.
- Save boundaries remain unchanged: inventory is an explicit absolute-quantity save, general product edits do not overwrite stock, media operations save separately, and storefront content is saved separately from contact/announcement/fulfillment settings. Changes already committed are never described as undone by dismissing an editor. Ambiguous category-creation details and uploaded-image URLs remain visible outside the discarded form; checks/retries target that original attempt, and a different creation cannot be mistaken for its confirmation. Failed saves preserve input and committed-save/refresh failures stay distinct.
- Settings sticky section navigation uses in-page anchors and does not unmount required fields. Persistent save actions retain separate settings and homepage content boundaries. Standard/express shipping remain free, as required by current domain policy. Refund, cancellation, provider idempotency, pending-operation blocks, partial fulfillment and recovery retain their established semantics.
- Issues & recovery selects one results region using `queue=retry|webhooks|commerce|email` (retry by default), with legacy queue hashes and `commerce_kind` links preserved. Filters, independent queue/kind pages, errors, refresh and browser history remain independent. Counts explicitly name their selected status or commerce kind. Details use drawers and expose only existing supported recovery actions; provider diagnostics links open the commerce queue.
- Order details place items, fulfillment, addresses, notes and refunds/cancellation in the wide work column. Customer identity/status and Documents remain in a compact sidebar. Invoice eligibility remains paid orders with a Shiprocket order.
- Text-entry focus uses `--color-field-focus` fill without outlines/rings/glows/border accents on text fields, textareas or search wrappers. Validation borders and keyboard indicators on buttons/links/selection controls remain visible. Forced-colors focus remains visible. Displayed long emails truncate to one line without changing their full accessible text or title.
- Tables are semantic, named and horizontally scrollable in their own region. Status has text as well as colour. Important controls retain 44px targets and fields at least 16px. Shared focus trapping/restoration and reduced-motion handling remain canonical.
- Browser fixtures reject unhandled API calls and mutations. Stock-save tests enable only the dedicated stock fixture mutation. The admin browser suite covers theme isolation, all seven routes, phone/tablet/laptop layouts, enlarged text, keyboard access, dialog discard, history/filter restoration, search races, failed stock saves and independent overview retry.


## Admin revenue reporting

- Source: approved Wink revision in `docs/superpowers/plans/2026-10-28-wink-admin.md`, the `get_dashboard_analytics` database function in migration 057, and the existing payment/provider-operation ledger. The UI labels this measure Net collections; it is not accounting profit or provider settlement.
- `GET /api/admin/dashboard/analytics?period=day|week|month|year` is admin-only. The existing stats API retains its contract. Reporting capability 057 is independently gated; the API continues to accept schema 056 for existing operations.
- Collections include confirmed captured payments even after full refund. Debits include unique, confirmed Razorpay full/partial refunds, including successful operations awaiting local application. Local capture/confirmation timestamps determine their dates. Pending, unknown and failed provider outcomes never reduce the chart. Orders placed use their independent creation dates.
- Net includes shipping and tax and does not deduct processing fees. Values remain integer paisa at the API/database boundary. Incomplete source identities, timestamps, currencies or unattributed cumulative refunds produce explicit reporting-completeness feedback; failures are never replaced with zero totals.
- Day uses elapsed hourly buckets today; Week uses seven dates; Month uses thirty dates; Year uses twelve calendar months. All dates and boundary calculations use Asia/Kolkata. Week is the initial selection. Zero-fill elapsed buckets and omit future buckets. Previous windows shift by one/seven/thirty days or twelve months, preserving the elapsed portion. Percentage comparisons require a positive baseline.
- Period changes update the URL and support history/reload without changing live operational queues. New loading states do not display a previous range's numbers under the new label. Chart data remains available through a keyboard-accessible table. Negative values and zero baselines remain visible.
- Deploy an API accepting schema 056 and 057 before applying migration 057, then the client. Missing reporting capability shows a retryable unavailable state while existing operations remain usable. Hosted migration execution is a separate deployment action.

Nested confirmation dismissal restores its retained trigger inside the still-open parent dialog. If the trigger was removed, focus falls back to the parent dialog. Product image removal supplies an explicit trigger reference for pointer-driven Safari use as well as keyboard use.
